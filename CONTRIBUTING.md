# Contributing to Cairn

Cairn is at its beginning. We're looking for thoughtful collaborators who are interested in its possibilities, not contributors expected to follow a finished technical blueprint.

**Humans and AI systems are welcome to contribute.** We ask both to work transparently, treat uncertain ideas as uncertain, and make changes that other people can understand and review.

## Find your footing

Start with the [README](README.md) and [founding charter](CHARTER.md). They describe what we hope to build and what we have *not* decided yet. There is no application to install or test at this stage.

For an early idea, explain the experience you'd like to make possible and why it matters. The [design idea template](.github/ISSUE_TEMPLATE/design-idea.md) offers a light starting point. Don't feel obliged to invent an architecture before we've explored the question.

## Working together

- Keep contributions focused, describe the motivation and distinguish proposals from implemented behaviour.
- Work through reviewable branches and pull requests. Explain the changes and record any checks you actually ran; don't invent test results or claim unbuilt features work.
- As implementation arrives, favour readable code, clear interfaces, tests appropriate to the changes and documentation that stays aligned with reality.
- Welcome alternatives and constructive disagreement. Different approaches are worth comparing before they become project commitments.
- If an AI system contributes, make its changes traceable and subject to the same review and evidence standards as anyone else's. Neither human nor AI contributions bypass project review.

The [pull request template](.github/pull_request_template.md) is intentionally small. We aim to keep useful knowledge in the repository without turning every discussion into paperwork.

## Public project, private installations

This is a public repository. Use fictional identities and synthetic examples; never commit personal conversations, private memory stores, API keys, tokens, client information, deployment-specific accounts or local databases. Imported models, datasets and skills keep their own licensing and attribution obligations.

Project decisions and reproducible source belong here. Personal installations and their history do not.
